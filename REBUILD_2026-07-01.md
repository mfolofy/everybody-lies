## 1. What the system actually is

House is the pre-commit review gate for every commit in this repo. The chain:

```
git commit
 └─ .git/hooks/pre-commit          (sh wrapper; scope/drift gate, fails OPEN on plumbing)
     └─ .git/hooks/pre-commit.house (launcher; interpreter probe, HOUSE_BYPASS early-exit)
         ├─ scripts/tools/house_sanitize.py   ← deterministic secret/gitignore/dot-artifact
         │                                       gate. Precise. Hard-blocks on P1. UNCHANGED.
         └─ python -m everybody_lies --staged  ← the review engine (this package)
             ├─ Cuddy pre-flight (stale subagents), tier resolution by risk
             ├─ scanner.py deterministic pre-scan (regex over ADDED lines)
             ├─ trivial fast-track (small/docs-only + clean scan → APPROVED, no LLM)
             ├─ Cuddy differential (LLM), specialists Foreman/Cameron/Chase/Taub/Thirteen
             │   (LLM, routed by file patterns; providers.call_llm behind everything)
             ├─ House synthesis (LLM) → verdict APPROVED/REJECTED
             └─ Wilson appeal pipeline (P1 = non-appealable, P2 = appealable)
```

Verdict mechanics: each specialist must emit a fenced ```` ```verdict ```` JSON block
(`_parse_structured_verdict`, gatekeeper.py). That block is the deterministic contract.
`all_pass` + `blocking_findings` + the synthesis text decide the final verdict; the CLI
exits 1 on REJECTED and the hook blocks the commit.

## 2. The exact bug (code path, old line numbers = `.bak-2026-07-01` copy)

The reported chain was "LLM unreachable → fell back to `scanner.py` regex heuristics."
**Reading the code, that is close but not the literal path.** Two distinct defects, both
of the same species (a heuristic regex fabricating non-appealable P1 verdicts):

1. **The scrape-P1 defect (the actual `"(fallback regex)"` message).**
   `gatekeeper.py:2038-2048` (primary path) and `gatekeeper.py:2090-2097` (fallback-model
   path): when a specialist response contains **no structured verdict block** — which is
   exactly what happens under degraded conditions (primary provider 529s → one hardcoded
   fallback model; or the response is **truncated at max_tokens** before the block is
   emitted, verified in the archived round
   `docs/reviews/archive/house-2026-07-01-...gmail_fetch...md`, where Thirteen's response
   cuts off mid-word) — the engine scrapes the free text with `P1_PATTERNS`
   (gatekeeper.py:1236) and appends `"{name}: P1 found (fallback regex)"` to
   `blocking_findings`.
   Then `gatekeeper.py:2303` — `has_p1 = any("P1" in bf for bf in blocking_findings)` —
   declares it **non-appealable**, and `run_appeal` (gatekeeper.py:2489-2516) auto-denies
   any appeal by re-scraping the markdown report (`^\s*[-|]\s*P1...`) — the same
   truncated text. Net: a provider outage or a token-truncated response manufactured an
   un-appealable hard block out of a regex guess.

2. **The scanner-severity defect (the "flagged legitimate subprocess/shell patterns"
   part).** `scanner.py` classified context-blind code-smell heuristics as **P1**:
   `shell-true-user-input` (any `shell=True`, scanner.py:159), `os-command-injection`
   (any `subprocess.run(f"...")`-shaped call, :127), `eval-exec-user-input` (:151),
   `sql-string-concatenation` (:119), `pickle-deserialization` (:134),
   `debug-true-production` (:143). Scan P1s hard-block the trivial fast-track
   (gatekeeper.py:1806) and auto-deny appeals — so a mesh launcher that legitimately
   spawns processes could be P1-blocked by regexes that cannot see context, with no LLM
   involved at all.

   (Bonus latent bug found while fixing: `run_appeal`'s scan check read
   `scan.get("p1_count")`, but the record stores counts under `summary.P1` — the scan
   half of the auto-deny had **never fired**. Fixed.)

3. **The all-providers-down defect.** If every specialist failed,
   `gatekeeper.py:2168-2183` set `verdict = "REJECTED"` ("All specialists failed") — an
   API outage bricked the commit workflow outright, contradicting the wrapper's own
   fail-open philosophy.

## 3. The degradation policy (stated plainly)

> **A reviewer that cannot review must degrade honestly, not fabricate blockers.**

- **Facts stay hard.** Deterministic, precise findings — `house_sanitize`
  (secrets/gitignore, unchanged), and scanner rules that detect literal secrets, tokens,
  private keys, and PII — remain **P1, blocking, non-appealable**, LLM up or down.
- **Real LLM verdicts keep their teeth.** A P1 declared in a structured
  ```` ```verdict ```` block from an actual model response blocks and is
  **non-appealable**, exactly as before.
- **Heuristics are labeled heuristics and are always appealable.** If a response has no
  structured block (truncation, degraded fallback), the regex scrape may still block —
  skepticism stays — but the finding is labeled
  `possible P1 [HEURISTIC — … appealable, not a verified verdict]` and never enters the
  non-appealable class. Scanner code-smell rules (shell=True, subprocess f-strings,
  eval/exec, pickle, DEBUG=True, SQL concat) are reclassified **P2**: surfaced to the
  board and the human, appealable, never a silent hard block.
- **Total outage → deterministic-only degraded review.** Providers are retried with
  backoff and failed over across every configured provider first. If ALL of them are
  still down: commit is **APPROVED (DEGRADED)** when the deterministic gates are clean,
  loudly labeled (`Signed: House (Gatekeeper) — DEGRADED…`, `degraded:
  "llm_unavailable"` in the record) with an instruction to re-run House when providers
  recover — and **REJECTED** if the scan found P1 facts or any other blocker exists.
- **Provenance is explicit.** Every finding now carries its source in its label
  (structured LLM verdict vs `[HEURISTIC]` scrape vs `Scanner: … deterministic scan`),
  and the review JSON records `hard_p1`, `blocking_findings`, and `degraded` so the
  appeal pipeline judges from structured data instead of re-scraping markdown.

## 4. What changed (files + specifics)

### `everybody_lies/providers.py`
- `call_llm`: per-provider **retry with backoff** (1 retry, 3s) on transient failures —
  HTTP 408/429/500/502/503/504/**529**, URLError/timeout. Hard failures (401/403,
  malformed response) fail over to the next provider immediately. Bounded so the hook's
  300s budget holds.
- New `available_fallback_models(exclude)`: ordered cross-provider fallback chain built
  from the API keys actually configured (DeepSeek → Gemini → Anthropic → OpenRouter).

### `everybody_lies/scanner.py`
- Six code-smell heuristics downgraded P1 → **P2** (listed above), with a
  "SEVERITY HONESTY" comment stating the rule: P1 is reserved for facts. All
  secret/token/key/PII patterns remain P1.

### `everybody_lies/gatekeeper.py`
- New `_assess_specialist_response()` — single shared classifier for both the primary
  and fallback paths (replaces two divergent copies of the verdict-parse + scrape
  logic). Structured P1 → `hard_p1=True`; scrape P1 → blocking, appealable,
  `[HEURISTIC]`-labeled; zero-count summaries still don't trigger.
- `run_review`: new `hard_p1_findings` list — **only** structured-verdict P1s and
  deterministic scan P1 facts enter it. The "not appealable" console branch and the
  record's `hard_p1` field key off it (was: substring `"P1" in bf`).
- Specialist failover now walks `available_fallback_models()` (up to 2 alternates,
  cross-provider) instead of one hardcoded `deepseek-v4-flash`.
- All-specialists-failed: **degraded verdict logic** — REJECTED if scan P1 facts or
  other blockers exist; otherwise APPROVED (DEGRADED) with loud labeling, provider
  failure detail, and re-review instruction in the synthesis and console.
- `review_data` now records `blocking_findings`, `hard_p1`, `degraded`, and a degraded
  `signed_by`.
- `run_appeal`: auto-deny now trusts the structured `hard_p1` field when present
  (markdown re-scrape kept only for legacy records); scan check fixed to read
  `summary.P1`.
- NOT touched: `HOUSE_BYPASS` handling, `house_sanitize`, the wrapper/launcher hooks,
  Cuddy tier logic, the trivial fast-track, `P1_PATTERNS` themselves,
  `_has_p1_findings()` (dead code — defined, never called; left as-is, noted here).
